## 2026-11-11 - Catastrophic Backtracking in Unanchored Schema Regexes
**Learning:** In MCP tool extraction (`aisec/extract.py`), regexes scanning JavaScript/TypeScript code blocks for Zod/JSON schema properties started with unanchored `(\w+)\s*:\s*...`. On long strings or descriptions without schemas (e.g. padded strings or non-schema code blocks), `\w+` backtracked character-by-character on mismatch, creating quadratic regex execution taking seconds. Adding `\b` boundaries eliminates the backtracking, and simple substring pre-checks (`:` and schema keywords) bypass regex searches completely on non-schema blocks.
**Action:** When scanning untrusted source code or metadata strings with regexes, always anchor with word boundaries (`\b`) to prevent `\w+` backtracking on mismatch, and guard heavy regexes with fast substring pre-checks.
